# Capability: Data Q&A Chat

## What It Does
Lets a user ask a natural-language question about one or more uploaded datasets and receive a real, computed answer (prose + optional table/chart) — generated by writing and executing real analysis code against the actual data, never a guessed or hallucinated figure. Asks a clarifying question instead of guessing when the question is genuinely ambiguous.

## Inputs
| Input | Type | Source | Required |
|-------|------|--------|----------|
| question | string | User chat message | yes |
| session_id | string | Existing session (bound to one or more dataset_ids) | yes |

## Outputs
| Output | Type | Destination |
|--------|------|-------------|
| Assistant turn | prose answer + optional table rows + optional chart spec + token/cost estimate | API response → chat UI |
| Clarifying question (when ambiguous) | prose question, no computation performed | API response → chat UI |

## External Calls
| System | Operation | On Failure |
|--------|-----------|------------|
| NVIDIA NIM LLM | classify intent / generate code / reflect on error / summarize answer | retry once, then surface "analysis temporarily unavailable" and log the failure |
| Local sandbox (`code_sandbox.execute`) | run generated pandas code against the real dataframe(s) | caught as a recoverable error, feeds the self-correction loop (see `spec/agent.md`); after 3 attempts, surfaced as a failure |
| Postgres | persist the turn and the audit-log row | fatal — the request fails rather than silently skipping the audit trail |

## Business Rules
- Raw dataset rows are never included in any LLM prompt — only column names, dtypes, and aggregate stats. This is a hard constraint, not a performance optimization.
- Generated code is read-only analysis — it must never mutate the loaded dataframe(s) or touch the filesystem/network.
- Up to 3 code-generation attempts are made per question (write → execute → see error → retry) before the question is reported as failed.
- A question spanning multiple datasets in the session can reference any of them by name in the generated code.
- The agent never shows the generated code or its internal reasoning in the chat UI by default (see `spec/ui.md`).

## Success Criteria
- [ ] Asking a simple factual question (e.g. row count, a column's distinct values) returns the real number, verifiable by inspecting the CSV directly.
- [ ] Asking a question that requires computation the first attempt gets wrong (e.g. a typo'd column reference in generated code) is silently self-corrected within the 3-attempt budget, without the user seeing the failed attempt.
- [ ] Asking a deliberately ambiguous question (e.g. referencing "the date column" when two date columns exist) produces a clarifying question, not a guess.
- [ ] A network capture of the LLM API call for any question shows no raw row values in the request body — only schema/stats/question/code.
